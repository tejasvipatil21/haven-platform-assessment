# B0 — The `count` trap

What does `terraform plan` show when a middle landlord account is removed from the list? Why is
that dangerous here? What's the fix?

Removing 'la-002' shifts the indexes of the accounts after it.
Terraform tracks 'count' resources by index, not by landlord account ID.

The plan replaces index '[1]' as it changes from 'la-002' to 'la-003',
and index '[2]' as it changes from 'la-003' to 'la-004'. Index '[3]', previously 'la-004', is destroyed because it is now out of range.
These were planned changes only, i did not apply them.

This is dangerous because removing one account can also disrupt buckets belonging to other accounts and potentially risk their data.

I would use 'for_each' keyed by the stable landlord account ID so removing one account does not shift the others addresses. for existing resources, i would migrate their state addresses using 'moved' blocks or a controlled state migration, then review the plan for unintended replacements or deletion before applying.
